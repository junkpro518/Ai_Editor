## ما هو
برومبت واحد يطلب من Claude تحويل أي مستودع إلى "خريطة نظام أيزومترية" تفاعلية:
`Analyze [repo] at latest main. Create an isometric system map with legend and explainer panel. Show infrastructure as varied 3D buildings on a grid, with dependencies and payloads tracing real control/data paths. Cite files.`
الاقتباس يشرح الفكرة: النقاط المتحركة هي "قصاصات بيانات" يمكن فحصها، ليسهل الحديث مع Claude عن الكود.

## الأفكار
- تحويل الكود إلى شكل بصري ليكون سياقاً مشتركاً بين الإنسان والنموذج.
- مباني مختلفة = أنواع بنية (قاعدة بيانات، API، طابور)؛ الأسهم/النقاط = مسارات تحكم وبيانات حقيقية.
- شرط "Cite files": كل عنصر يشير إلى ملف حقيقي — يقلل الهلوسة.
- لوحة شرح (explainer panel) ومفتاح (legend).

## التقنيات والبنية
- المعمارية: خرج HTML/Three.js أو SVG أيزومتري يُولَّد من النموذج. أمثلة: نص البرومبت أعلاه.

## أشياء نأخذها لمشروعنا
- **"خريطة المشروع" للمحرر**: خريطة أيزومترية للتايم لاين/القصة (مشاهد = مبانٍ، انتقالات = مسارات) يستطيع الوكيل والمستخدم مناقشتها. يخدم: الوكيل + المحرر.
- **خريطة معمارية لمشروعنا نحن** (محرر + وكيل + MCP + نظام أنماط) تولّد بنفس البرومبت لوثيقة التصميم. يخدم: توثيق.
- **الاستشهاد بالملفات** كقاعدة لمخرجات الوكيل: كل اقتراح نمط يشير إلى اللقطات التي استخرج منها.
- **نقاط متحركة على مسارات** مفردة حركة مناسبة لعرض "تدفق بيانات الفيديو" في فيديوهات شرح (تتكامل مع stagger وmotion path في anime.js).

## استلهامات
- طريقة التسويق: فيديو قصير + برومبت قابل للنسخ في سطرين؛ جمهور يحفظ البرومبت.

## تحذيرات ومخاطر
- جودة الخريطة تعتمد على قدرة النموذج وحجم المستودع؛ قد تُهلوس مسارات.
- لا يوجد مثال مرئي محفوظ لدينا.
