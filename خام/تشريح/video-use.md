## ما هو (3–6 أسطر)
مهارة من فريق browser-use تجعل Claude Code (أو Codex وغيره) محرر فيديو: تضع اللقطات الخام في مجلد وتحادث الوكيل فيُخرج `edit/final.mp4`. الفكرة الجوهرية: "الـLLM لا يشاهد الفيديو بل يقرؤه" — تفريغ بتوقيت الكلمة (~12KB نص لكل اللقطات) + صور مركّبة (filmstrip + موجة صوت + كلمات) عند الحاجة فقط. القرار يُكتب في EDL بصيغة JSON ثم يُصيّر بـffmpeg ويُقيّم ذاتياً.

## الأفكار (قائمة)
- "Text + on-demand visuals": مثل إعطاء المتصفح DOM بدل لقطة شاشة.
- الصوت أساسي والصورة تتبعه: القص من حدود الكلام والصمت.
- اسأل → أكّد الخطة → نفّذ → قيّم ذاتياً → احفظ الذاكرة.
- 12 قاعدة صلبة للصحة التقنية، وحرية فنية في الباقي.
- وكيل ناقد (critic) منفصل "يحمّص" الناتج قبل التسليم.

## المميزات (قائمة، ما يفعله فعلاً لا ما يدّعيه التويت)
- حذف كلمات الحشو والبدايات الخاطئة والفراغ بين اللقطات، مع قصّ على حدود الكلمات وحشوة 30–200ms.
- تصحيح ألوان لكل مقطع بسلسلة ffmpeg (presets أو `--filter` خام) عبر `grade.py`.
- fade صوت 30ms عند كل قطع.
- كابشن محروق (افتراضياً كلمتان UPPERCASE) من `master.srt`.
- رسوم متحركة عبر HyperFrames أو Remotion أو Manim أو PIL، كل واحدة في وكيل فرعي متوازٍ.
- تقييم ذاتي عند كل حد قطع في الناتج (حتى 3 دورات) + قياس الصوت `ebur128`.
- ذاكرة جلسات في `project.md`.
- **ليس "بدون تايم لاين" بمعنى سحري**: هناك EDL، ولا يوجد تايم لاين بصري قابل للتحرير يدوياً.

## التقنيات والبنية
- الحزم/المكتبات: ElevenLabs Scribe (`scribe_v1`، API مدفوع) للتفريغ مع diarization وأحداث صوتية؛ ffmpeg للتصيير؛ librosa/matplotlib لـ`timeline_view`.
- المعمارية: `transcribe.py` → `pack_transcripts.py` (→ `takes_packed.md`) → الوكيل يكتب `edl.json` → `render.py` (استخراج كل مقطع مع grade و fades → concat بـ`-c copy` → overlays بـ`setpts=PTS-STARTPTS+T/TB` → subtitles أخيراً) → `timeline_view.py` على الناتج. كل المخرجات في `<videos_dir>/edit/`.
- مخطط EDL:
  `{"version":1,"sources":{"C0103":"/abs/path"},"ranges":[{"source","start","end","beat","quote","reason"}],"grade","overlays":[{"file","start_in_output","duration"}],"subtitles","total_duration_s"}`
- أمثلة ملموسة: القاعدة 5 — `output_time = word.start - segment_start + segment_offset`؛ القاعدة 7 — انجراف Scribe 50–100ms؛ مضاد-نمط: "Hand-tuned moment-scoring functions. The LLM picks better".

## أشياء نأخذها لمشروعنا
- **EDL بحقول `beat/quote/reason` لكل مقطع**: كل قرار قص يحمل تبريراً يعرضه المحرر ويتعلم منه النمط — **الوكيل/نظام الأنماط**.
- **تمثيل الفيديو للوكيل نصاً + صور عند الطلب**: يخفض التكلفة جذرياً ويناسب التشغيل المحلي/الهجين — **الوكيل**.
- **القواعد الـ12 كحواجز تقنية ثابتة** (الكابشن آخراً، fades، القص على حدود الكلمات، كاش التفريغ…) منفصلة عن "الذوق" الذي يحدده النمط — **التصدير/نظام الأنماط** (يطابق "القواعد الإلزامية مقابل التفضيلات" في الرؤية).
- **حلقة تقييم ذاتي محدودة بـ3 + وكيل ناقد** قبل عرض المعاينة — **الوكيل**.
- **`project.md` ذاكرة جلسات**: بذرة لذاكرة المشروع، ونحن نعمّمها إلى ذاكرة نمط عبر المشاريع — **نظام الأنماط**.
- **الموافقة على الاستراتيجية قبل التنفيذ** — يطابق وضع "خطة للمراجعة" — **الوكيل**.

## استلهامات
- عبارة "The LLM never watches the video. It reads it" والمقارنة الرقمية "45M tokens vs 12KB" — شرح مقنع جداً.
- برومبت إعداد واحد يُلصق في الوكيل فيثبّت كل شيء.
- قائمة انتظار لنسخة سحابية (video-use.com) — نموذج "مفتوح محلي + سحابي مدفوع".
- التويتات العربية والإسبانية متطابقة تقريباً (قالب فيروسي مترجم)؛ الجمهور يتفاعل مع "بدون تايم لاين، بدون نقرات".

## تحذيرات ومخاطر
- التفريغ **مدفوع وسحابي** (ElevenLabs API key إلزامي) رغم ادعاء التويتات "مجانية بالكامل".
- لا تايم لاين بصري للتعديل اليدوي — عكس رؤيتنا.
- تصحيح الألوان مجرد سلسلة ffmpeg، و"الأنيميشن السلس" يعتمد على أدوات خارجية.
- مقارنة "يجعل Remotion من الجيل القديم" تسويقية؛ المشروع نفسه يستخدم Remotion اختيارياً.
- دقة Scribe مع العربية غير مختبرة هنا.
