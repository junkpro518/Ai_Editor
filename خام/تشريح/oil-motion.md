## ما هو (3–6 أسطر)
مهارة لصنع **رسوم ويب تفاعلية** من فيديو AI: تتبع التمرير، الماوس، السحب، اللمس، ميلان الجهاز (مثل منتج يتفكك "انفجارياً" مع التمرير على طريقة Apple). الوكيل يحدد الإطارات المفتاحية، يولّد الحركة بينها بنموذج فيديو، ينظف الإطارات، يضغط الأصول، ثم يربطها بمدخل التفاعل. مستقل عن المونتاج؛ README يقول صراحة إن "مونتاج الأفلام المستقلة" خارج النطاق.

## الأفكار
- **الإطارات المفتاحية أولاً ثم الحركة بينها**: تثبيت البداية والوسط والنهاية يمنع النموذج من تغيير هوية المنتج أثناء التوليد.
- الفصل بين ما يولّده الذكاء (تحول الشكل، الخامات، الحجب) وما يتحكم فيه الكود (إزاحة، تكبير، سرعة، تخميد).
- "بوابة إنتاج" قابلة للتدقيق: لا يُنتقل للمرحلة التالية إلا بأدلة معتمدة (`conceptContract, firstFrame, lastFrame, pilotVideo, pageEvidence`).
- تنظيف الإطارات: حذف التوقف والتكرار والإطارات الشاذة (`loop_cleanup.py`).

## المميزات
- سكربتات: `image_job.py, video_job.py, chroma_key.py, composite_alpha_keyframe.py, compile_scroll_video.py, optimize_motion.py, motion_budget.py, production_gate.py, create_explainer.py`.
- مراجع: أنماط حركة، اختيار طريقة التسليم (فيديو مخبوز/أطلس ألفا/Chroma)، QA، تحسين الحجم.
- مفتاح API يُخزن في مخزن بيانات اعتماد النظام عبر صفحة إعداد محلية، لا في الشات.
- Evals واختبارات انحدار للمهارة.

## التقنيات والبنية
- الحزم/المكتبات: Python + Pillow + YAML؛ التوليد عبر **ZenMux** (`ZENMUX_API_KEY`) — وسيط لنماذج صور/فيديو مدفوعة.
- المعمارية: عقد مفهوم YAML (مفاتيح مكررة مرفوضة) ← إطارات مفتاحية ← Pilot ← فيديو ← تنظيف ← ضغط حسب حجم العرض الفعلي ← كود ويب.

## أشياء نأخذها لمشروعنا
- **"ثبّت الإطارات المفتاحية ثم ولّد بينها"** لأي توليد B-roll/انتقالات AI — يقلل الهلوسة — التوليد.
- **بوابات موافقة بأدلة (pilot قبل الإنتاج الكامل)** للعمليات المدفوعة — التكلفة/الوكيل.
- **تخزين مفاتيح API في keychain عبر صفحة محلية** بدل لصقها في الشات — الأمان (الرؤية §12).
- **ميزانية الحركة/الحجم** قبل التوليد — التكلفة.
