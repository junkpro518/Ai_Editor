# 0. حالة الوثيقة وطريقة قراءتها

هذه الوثيقة تجمع ما طرحه صاحب الفكرة وما تم الاتفاق عليه خلال النقاش، وتفصل عنه اقتراحات المساعد والقرارات المؤجلة. المستودعات المذكورة مرشحة للدراسة فقط؛ لم تُثبّت أو تُختبر عمليًا، ولم تُراجع جميع ملفاتها أو تراخيصها القانونية تفصيليًا. لا تعني الإشارة إلى ميزة في README أنها ناضجة أو صالحة للدمج.

# 1. الرؤية والهدف

منتج يتيح لصانع المحتوى رفع مواده الخام، وإنشاء نمط مونتاج خاص به أو استنتاجه من فيديوهات مرجعية، ثم تكليف وكيل ذكاء اصطناعي بتطبيق النمط على مشروع فيديو حقيقي قابل للتعديل داخل محرر متعدد المسارات. يمكن للمستخدم تعديل النتيجة يدويًا أو بالمحادثة، ويقترح الوكيل تطوير النمط استنادًا إلى التصحيحات بعد موافقة صريحة.

الفرضية المميزة: قيمة المنتج ليست مجرد تحرير الفيديو بالأوامر؛ بل حفظ أسلوب المستخدم وإعادة تطبيقه وتحسينه عبر أعمال متكررة. هذه فرضية منتج لم تختبر تجاريًا بعد.

# 2. المستخدمون وسيناريوهات الاستخدام

• صانع محتوى ينشر بانتظام ويريد الحفاظ على هوية بصرية وإيقاع ثابت.

• محرر مستقل يدير أنماطًا مختلفة لعملاء متعددين.

• قناة تعليمية تحتاج المحافظة على خطوات الشرح وعدم حذف معلومات أساسية.

• قناة دينية تحتاج حذرًا خاصًا في القص والسياق والترجمة، مع مراجعة بشرية لازمة.

• صاحب بودكاست يريد قص مقاطع قصيرة وترجمة وحركة نصوص مع القدرة على التدخل اليدوي.

الجمهور الأول المستهدف لم يُحسم بعد؛ اقتراح البحث الأولي هو اختبار صناع المحتوى المتكرر، وليس افتراض أنهم الأفضل تلقائيًا.

# 3. تجربة الاستخدام من البداية للنهاية

• إنشاء مشروع، اختيار أبعاد الفيديو ومعدل الإطارات واستيراد المقاطع والصوت والصور.

• إنشاء نمط جديد: من إعدادات مرئية، أو وصف باللغة الطبيعية، أو مقاطع مرجعية، أو دمج هذه الطرق.

• إدخال فيديوهات مرجعية بالرفع أو روابط يوتيوب/تيك توك/إنستغرام حيث تسمح آليات الوصول والشروط والحقوق.

• تحديد عناصر الاقتباس من كل مرجع: القص من فيديو، الخطوط من آخر، الحركة من ثالث.

• تحليل المحتوى والنمط وإظهار حدود الثقة والخصائص التي لم تُستنتج بدقة.

• اختيار وضع التنفيذ: تلقائي، أو خطة للمراجعة ثم التنفيذ؛ ويمكن إعداد عتبات موافقة للتغييرات الحساسة.

• توليد مشروع قابل للتحرير: مسارات فيديو وصوت وترجمة وطبقات ورسوم وحركات.

• المعاينة والمقارنة والتعديل عبر Timeline أو محادثة؛ التراجع وسجل العمليات متاحان.

• اقتراح تحديث قواعد النمط بعد ملاحظات المستخدم، مع عرض الفرق وطلب الموافقة قبل الحفظ الدائم.

• التصدير محليًا قدر الإمكان؛ المزامنة والسحابة والعمليات التوليدية الثقيلة اختيارية بحسب التكلفة.

# 4. نظام الأنماط — قلب المنتج

## 4.1 محتوى النمط

• الهوية: الاسم والوصف والفئة والصورة المصغرة والمالك واللغة والإصدار.

• قواعد القص: حذف الصمت، الإيقاع، حدود القص، المحافظة على السياق، الاستثناءات.

• النصوص والترجمة: الخط والحجم واللون والموضع وعدد الأسطر وحركة الظهور وقواعد التدقيق.

• الحركة والمؤثرات: انتقالات، تكبيرات، موشن جرافيك، عناصر متكررة، مدة الحركة.

• الصوت: مستويات المزج، تنظيف الصوت، موسيقى أو بدون موسيقى، مؤثرات ووقفات.

• المشهد والتكوين: نسب الأبعاد، الهوامش الآمنة، موضع المتحدث، القص العمودي.

• القواعد الإلزامية مقابل التفضيلات: ما يُمنع وما يُفضل، وإجراء التعامل مع تعارض القواعد.

• الأصول المرتبطة: شعارات وخطوط وخلفيات ومؤثرات مع تراخيص الاستخدام.

• المراجع: روابط أو ملفات الإلهام والخصائص المستخلصة منها، بدون تضمين ملفات لا يملك المستخدم حقوقها.

• مستوى استقلالية الوكيل والموافقات المطلوبة، وإعدادات الخصوصية.

## 4.2 إنشاء الأنماط وتطويرها

• إنشاء يدوي كامل عبر لوحة إعدادات مرئية.

• إنشاء بالمحادثة: تحويل تعليمات المستخدم إلى حقول منظمة قابلة للمراجعة.

• إنشاء من مقاطع مرجعية مع استخراج خصائص تقريبية لا وعد باستنساخ النتيجة حرفيًا.

• مزج عناصر عدة مراجع وتوضيح مصدر كل قرار.

• مختبر أنماط: تجربة A/B/C على مقطع قصير ثم حفظ النسخة المختارة.

• تعلم تفضيلات المستخدم من التصحيحات؛ يطبّق التصحيح على المشروع أولًا ثم يقترح تحديث النمط.

• تاريخ إصدارات مع مقارنة فروقات، تراجع، استنساخ نمط، وتصدير/استيراد حزم Style Pack.

• إمكان مشاركة الحزم وبيعها لاحقًا بعد حل حقوق الأصول وتوافق الإصدارات.

• تطبيق أنماط متعددة على أجزاء من الفيديو، مع قواعد أولوية عند التعارض؛ ميزة متقدمة.

## 4.3 مثال حساس: النمط الديني

قواعد محتملة: عدم قص آية أو حديث بما يغيّر المعنى، عدم تغيير ترتيب الكلام دون تنبيه، الحذر في تفريغ النصوص الشرعية، الامتناع عن إضافة موسيقى وفق تفضيلات صاحب القناة، تمييز النصوص المقتبسة، وإلزام مراجعة بشرية قبل النشر. لا يمكن الاعتماد على الوكيل وحده لضمان سلامة المعنى أو صحة النقل.

# 5. محرر الفيديو ومحرك التنفيذ

• Timeline متعدد المسارات مع القص والسحب والدمج والفصل والتحريك والتكبير والتحجيم وتعديل السرعة.

• معاينة مطابقة للتصدير قدر الإمكان، وUndo/Redo ولقطات حالة وAutosave.

• مسارات منفصلة للفيديو والصوت والترجمة والرسوم، ومفاتيح حركة Keyframes.

• تمثيل موحد للمشروع (Project Document) وعمليات تعديل منظمة قابلة للتحقق والتراجع.

• الوكيل لا يغيّر ملفات المصدر مباشرة؛ يقترح أوامر على نموذج المشروع ويُظهر أثرها.

• تغييرات حساسة كحذف جزء طويل أو إعادة ترتيب الكلام تتطلب موافقة بحسب إعداد النمط.

• تمييز العناصر القابلة للتحرير عن الوسائط المولدة المسطحة مثل فيديو مولّد مسبقًا.

• مكتبة أصول ذكية وحفظ قوالب النصوص والحركات والتأثيرات المستخدمة بكثرة.

# 7. التوليد والمزايا المتقدمة

• ترجمة تلقائية، تفريغ كلام، محاذاة كلمات، ترجمة لغوية وتعديل التوقيت.

• توليد صور، مشاهد فيديو، تعليق صوتي، مؤثرات، رسوم توضيحية وموشن جرافيك.

• المراجعة الذكية قبل التصدير: أخطاء قص محتملة، مستويات صوت، خروج نص عن إطار، أخطاء ترجمة.

• مونتاج دفعي مع قائمة انتظار وحدود استهلاك وتكلفة واضحة.

• تصدير مقاسات متعددة من المشروع نفسه.

• المزامنة عبر الأجهزة، التعاون بين أعضاء الفريق، مراجعات وتعليقات، ومتجر أنماط مستقبلًا.

• التمييز بين «توليد مشهد جديد» الذي قد يحتاج API مدفوعًا و«تحريك عناصر محرر» الذي يمكن تنفيذه محليًا.

# 8. المنصات والتشغيل والتكلفة

اتجاه المستخدم: الكمبيوتر أولًا، والجوال لاحقًا؛ دعم المنصتين هدف مستقبلي. التشغيل المفضل هجين/محلي أولًا لتقليل التكلفة: ملفات الفيديو والمعاينة والتصدير على جهاز المستخدم قدر الإمكان، وطلبات النماذج عبر الإنترنت عند الحاجة، مع خيار سحابي مدفوع للأعمال الثقيلة. ليس محسومًا بعد هل ستكون النسخة الأولى تطبيق سطح مكتب أصليًا أو محرر ويب محليًا داخل غلاف سطح مكتب.

الاشتراكات: اشتراك ChatGPT أو Claude الشخصي لا يعني تلقائيًا وجود رصيد API قابل للاستهلاك في تطبيق مستقل. خيارات المنتج: BYOK بمفاتيح API، أو رصيد ضمن باقاتنا، أو نموذج هجين. استخدام MCP مع عميل مدعوم مختلف عن إعادة بيع اشتراك شخصي. يجب مراجعة شروط كل مزود قبل اختيار المسار.

بنود التكلفة: تحليل الكلام والفيديو، النماذج متعددة الوسائط، توليد الفيديو والصور، التخزين والمزامنة، نقل البيانات، معالجة GPU، التصدير السحابي، الدعم. لا توجد تقديرات مالية موثوقة بعد دون قياس حالات اختبار محددة.

# 10. المستودعات التي ذُكرت في النقاش وتحققنا منها الآن

## MakeMyClip/editor

الرابط: https://github.com/MakeMyClip/editor

سبب الاهتمام: محرر محلي وCLI وMCP وAgent Skill؛ أدوات FFmpeg محددة وسجل عمليات. مناسب لدراسة واجهة أوامر الوكيل. README يذكر API قبل 1.0؛ يحتاج اختبار.

تنبيه: ترخيص MIT مذكور في النقاش السابق؛ يجب التأكد من LICENSE الفعلي وتبعيات FFmpeg قبل الاعتماد.

## OpenChatCut

الرابط: https://github.com/jeongpiano/openchatcut

سبب الاهتمام: محرر محلي متعدد المسارات، شات، MCP، Skills، Remotion/FFmpeg ونسخ سطح مكتب. مرشح قوي للمقارنة المرجعية.

تنبيه: AGPL بحسب README؛ مخاطرة لمنتج مغلق ويحتاج تقييمًا قانونيًا.

## OpenVideo Editor

الرابط: https://github.com/openvideodev/react-video-editor

سبب الاهتمام: محرر React متعدد المسارات وتصدير محلي WebCodecs/PixiJS، مثال لبنية محرر ويب.

تنبيه: README الحالي يذكر ترخيصًا مزدوجًا وحدّ 3 موظفين للرخصة المجانية؛ لا تفترض حرية استخدام تجاري غير مشروط.

## Cutaway

الرابط: https://github.com/S07K/cutaway

سبب الاهتمام: محرر local-first في المتصفح، timeline ومعاينة WebGL وترجمة محلية وتصدير؛ مناسب لدراسة الأداء المحلي.

تنبيه: تطوير نشط وPlugin SDK في خارطة الطريق؛ افحص النضج والترخيص.

## Timeline Studio

الرابط: https://github.com/MartinDelophy/ai-video-editor

سبب الاهتمام: مشروع قابل للتحرير من المستخدم والوكيل، مهارة edit-timeline-studio وتصدير محلي وأمثلة WebMCP.

تنبيه: README يوضح أن بعض التخطيط يعتمد على metadata لا تحليل كامل للوسائط؛ اختبر حدود الوكيل.

## LosslessCut

الرابط: https://github.com/mifi/lossless-cut

سبب الاهتمام: مرجع لقص الوسائط السريع غير المعيد للترميز باستخدام FFmpeg، ليس أساسًا كافيًا لمحرر أنماط.

تنبيه: GPL-2.0 بحسب المستودع؛ افحص أثر إعادة استخدام الكود.

# 12. مخاطر يجب ألا تُنسى

• مخاطر حقوق الملكية: تحليل فيديوهات مرجعية لا يمنح حق إعادة نشرها أو تضمين أصولها في حزمة نمط.

• المنصات: لا نَعِد بجلب أي رابط؛ يعتمد على API والتصاريح والشروط وإمكانية الوصول.

• الأمان: منع وصول الوكيل غير المقيد لملفات الجهاز، حماية مفاتيح API، تأكيد الأوامر المدمرة.

• الخصوصية: توضيح ما يخرج إلى مزود AI، ووسائل حذف الملفات والبيانات.

• الدقة: أخطاء الترجمة أو تحريف السياق خصوصًا للمحتوى الديني والطبي والتعليمي.

• الترخيص: AGPL/GPL والترخيص المزدوج وتبعيات FFmpeg والأصول والخطوط والنماذج.

• التكلفة: عدم تسعير اشتراك غير محدود قبل معرفة تكلفة كل دقيقة معالجة وتوليد.

• تشتت النطاق: بناء Premiere كامل وتوليد فيديو ومتجر وجوال دفعة واحدة يرفع احتمال التأخير.

• السوق: وجود محررات مفتوحة المصدر بالفعل؛ الفارق يجب أن يثبت بتجربة مستخدم لا بوصف تسويقي.

# 13. أسئلة بحث مفتوحة

• من المستخدم الأول الذي يعاني المشكلة أكثر؟ وما معدل إنتاجه ومقدار الوقت الذي يهدره؟

• هل يمكن استنتاج نمط مفيد من 3–5 فيديوهات مرجعية أم يحتاج أمثلة أكثر؟

• كيف نمثل القواعد الإلزامية والمرنة والتعارضات والنسخ؟

• أي محرر يحقق تحريرًا حقيقيًا بعد تنفيذ الوكيل، وتوافق معاينة/تصدير؟

• هل نستخدم قاعدة محرر موجودة أم محركًا خاصًا؟ وما تكاليف الترخيص والصيانة؟

• هل أول إصدار يعمل كويب محلي، أم Electron/Tauri، أم تطبيق أصلي؟

• ما دقة تفريغ العربية واللهجات، وما تكلفة التحليل للمقطع الطويل؟

• هل تكفي API نماذج عامة للتخطيط أم نحتاج رؤية/صوت/فهم زمني متخصص؟

• ما سياسة صلاحيات الوكيل، وسجل العمليات، والتراجع، وحفظ الملفات؟

• كيف ندعم الجوال لاحقًا دون إعادة كتابة المنطق كله؟

• كيف سيعمل BYOK، وماذا يحدث عند نفاد الرصيد أو فشل المزود؟

• ما المعايير التي تجعلنا نوقف المشروع أو نغير اتجاهه مبكرًا؟
